# Spec — UX Taste (design review pass + frontend taste discipline)

Version: 1.0 (2026-08-10). Approved via brainstorm. v2.1 track.

## Goal

Give the loop a real UX dimension on both sides: prevention
(`meta/frontend-taste`, activated when building user-facing work) and
detection (an upgraded `uiux-engineer` review pass wired into
`meta/delivery-loop` as a conditional gate). Distilled from three
licensed sources with full attribution. Rules become findings; taste
becomes explicitly flagged human decisions — never silently resolved.

## Sources (licenses verified 2026-08-10)

1. **Leonxlnx/taste-skill** (MIT) — `skills/taste-skill/SKILL.md`
   "Design Engineering Directives": typography bias correction, color
   calibration, layout hard rules, forbidden animation patterns,
   mandatory reduced-motion, interactive states, density guidance.
2. **Dragoon0x/taste-skills** (MIT) — `skills/perception/visual-audit`
   critique protocol: observations not feelings; banned vague words
   (clean, nice, modern, sleek, beautiful, stunning, minimal, bold);
   output structure intent → working → not working → single
   highest-impact change; anti-patterns (politeness-only, solutioning
   before diagnosis, style preference vs quality signal). Plus the
   visual-language set (hierarchy, spatial rhythm, color systems,
   type systems) as distillation input.
3. **anthropics/skills `frontend-design`** (Apache-2.0) — the three
   AI-slop cluster looks (warm cream + high-contrast serif +
   terracotta; near-black + single acid accent; broadsheet hairlines
   + zero radius); spend-boldness-in-one-place restraint; quality
   floor (responsive, visible focus, reduced motion); UX-writing
   rules (copy as design material, active voice, exact action names
   kept consistent through a flow, errors direct and never
   apologetic, empty states as invitations).

Adaptation discipline as before: fetch actual text at implementation
time, distill (do not paste wholesale), provenance line on every
adapted file, full license texts in THIRD-PARTY-NOTICES.md (Apache
2.0 requires its full text; include the LICENSE.txt from the skill
directory). Unlicensed/derivative repos (senlindesign, h3nryprod01)
are not sources.

## 1. Knowledge files — `src/crucible/knowledge/`

Three new bundled knowledge files (14 → 17), each opening with a
provenance line naming its sources:

- **`design-taste.md`** — typographic scale and pairing; spacing
  rhythm and grid consistency; color roles and calibration;
  hierarchy (where the eye goes first, and is it intentional);
  density matched to use case; materiality/shadows; the three
  AI-default cluster looks as *default-detection* signals (a default
  is not a choice); anti-default discipline.
- **`motion-interaction.md`** — purposeful motion only; forbidden
  animation patterns; reduced-motion support mandatory; the full
  interactive-state matrix (hover/focus/active/disabled/loading/
  empty/error); timing and feedback.
- **`ux-writing.md`** — copy is design material; write from the
  user's side of the screen; active voice, exact verbs ("Save
  changes", not "Submit"); one action keeps one name through a flow;
  errors explain and direct, never apologize or go vague; empty
  states invite action.

All three are review-usable AND build-usable: each rule phrased so a
reviewer can cite it and a builder can follow it.

## 2. `uiux-engineer` upgrade (persona, adapted)

Keep the existing mechanics checklist (states, tokens, touch
targets, responsiveness). Add:

- **Critique protocol** (from visual-audit): findings state
  observations, not feelings; the banned vague words list, verbatim;
  review output ordered intent → working → not working → the single
  highest-impact change.
- **Default detection**: the three cluster looks + template-answer
  patterns flagged as "default, not a choice" findings.
- **The rule/taste split (binding):** objective violations (design
  tokens bypassed, missing states, contrast, reduced-motion absent,
  vague copy) are findings with severity. Subjective calls
  (palette direction, typographic personality, density preference,
  signature element) are listed under a separate `TASTE (human
  call):` heading — never given a severity, never block, never
  silently resolved by the agent.
- **Design-system-first rule:** where the project has a design
  system, compliance with it outranks any taste rule in this pass.
- Tier-3 pointers to the three knowledge files; provenance line
  naming all three sources; version bump.

## 3. `meta/frontend-taste` (new skill)

The generation-side counterpart to `meta/coding-discipline`:
activates on frontend/UI building intent. Professional register.

- Before writing UI code: a one-line design read (what this is, who
  it serves, what tone fits) — stated, not assumed.
- Anti-default discipline: no reaching for the three cluster looks
  or template answers when an axis is free; deliberate choices,
  specific to the brief; spend boldness in one place.
- Hard rules (binding list in the skill): design system first when
  one exists; full interactive-state matrix; reduced motion
  respected; purposeful animation only; copy per `ux-writing.md`;
  responsive floor; visible keyboard focus.
- Tier-3 pointers to the same three knowledge files.
- Do-NOT boundary: not for backend/non-visual work; never redesign
  surfaces the task didn't touch; never override an existing design
  system for taste; taste disagreements with the human are theirs to
  win.
- Triggers (conservative): building/styling UI phrases ("build a
  page", "landing page", "style this component", "dashboard UI",
  "frontend taste"); negative case: "design the database schema"
  must not fire it.

## 4. Loop wiring

- `meta/delivery-loop` step 5: one added sentence — when the change
  touches user-facing surfaces, the independent review includes the
  UX pass (`uiux-engineer`, with `accessibility-engineer` alongside)
  and its `TASTE (human call)` items go to the human with the
  review, unresolved.
- `meta/engineering-loop` step 4 area + `docs/LOOP.md`: one gentle
  sentence each — building something people will see → activate
  `meta/frontend-taste`.
- CLAUDE.md one-liners (frontend-taste + uiux upgrade note); counts:
  skills 40 → 41, knowledge 14 → 17, everywhere they appear.

## Acceptance criteria

1. Discover lists 41; frontend-taste triggers: positive match + the
   "design the database schema" negative case in the router tests.
2. Content assertions: uiux-engineer contains the banned-words list,
   the `TASTE (human call)` split, and the design-system-first rule;
   frontend-taste contains the Do-NOT boundary and the hard-rules
   list; all adapted files carry provenance lines.
3. THIRD-PARTY-NOTICES.md gains all three attributions including the
   full Apache-2.0 text from the source skill's LICENSE.txt; a test
   asserts all three copyright/attribution markers.
4. Knowledge files load via the knowledge loader (test by name);
   knowledge count updated everywhere it appears in docs.
5. delivery-loop names the conditional UX gate (content assertion);
   wheel ships the new skill + knowledge files; full suite green at
   954 baseline + new tests; ruff clean.

## Non-goals

- No screenshot/visual-diff tooling, no browser automation in review
  (rules operate on code and copy; visual QA stays human).
- No new assertion files (pattern assertions for UI are a possible
  follow-up, not this cycle).
- No changes to accessibility-engineer (already strong); no
  redesign/generation of any existing crucible UI surfaces.
- No release/tag.
